# プライバシーポリシー

本プライバシーポリシーは、{{LEGAL_OPERATOR_NAME}}（「当社」「私たち」または「Check Station」）が Check Station サービスに関連して情報をどのように取り扱うかを説明します。

Check Station は、組織がチェックイン、チェックアウト、出席、および関連するアクティビティ追跡ワークフローを設定・運用するために使用するマルチテナント型ソフトウェアプラットフォームです。単一企業のタイムクロックではなく、特定の業界に限定されません。

本ポリシーに同意しない場合、Check Station を使用しないでください。

## 1. 適用範囲

本ポリシーは以下に適用されます:

- Check Station ウェブサイトおよびワークスペース
- オーナーおよびワークスペーススタッフの認証
- 顧客が設定したキオスクの運用
- プラットフォームのトランザクションメール
- 請求およびサブスクリプション管理
- 公開 Status ウェブサイトおよび関連する公開ステータスデータ
- 公開ドキュメント、サポート、法務ページ
- 公開お問い合わせフォームおよび関連するお問い合わせリクエスト

本ポリシーは、Check Station が以下について責任を負うものでは**ありません**:

- 顧客が Check Station **外**で収集または使用する情報
- 顧客がスタッフ、メンバー、生徒、ビジター、その他の参加者に対して提供する独自のプライバシー通知
- 顧客が**顧客設定のグループメール**（SMTP 等）を通じて送信するコンテンツ（以下に記載する範囲を除く）

## 2. Check Station の運営者

Check Station は {{LEGAL_OPERATOR_NAME}} により運営されています。

専用の運営者法人名、登記住所、主たる事業所は、製品アイデンティティ **Check Station** を超えて本ポリシーで指定されていません。それらの詳細が指定されるまで、プライバシーに関するお問い合わせは {{LEGAL_CONTACT_EMAIL}} または Check Station ウェブサイトの公開お問い合わせページへご連絡ください。

プラットフォームのトランザクション通知は、設定された Check Station アカウントメールボックス（顧客環境で別途設定されない限り、現在 `accounts@checkstation.app` として使用）から送信されます。このアドレスはアカウントメールの送信元です。それ自体が保証された受信プライバシーヘルプデスクではありません。

## 3. 役割: 顧客と Check Station

**顧客**（有料ワークスペースオーナーとその組織）は、Check Station に入力する人物、グループ、キオスク設定、写真、メールを決定します。顧客が入力した参加者およびメンバーデータについて、顧客は当該処理の目的を決定する組織です。Check Station は、サービスとして当該データを保存・処理するために使用するソフトウェアを提供します。

**Check Station** が処理目的を決定するもの:

- オーナーアカウントの登録と認証
- ワークスペーススタッフログインインフラ
- サービスセキュリティ、不正利用防止、プラットフォーム管理
- 請求およびサブスクリプションレコード
- プラットフォームのトランザクションメール
- 公開ステータス報告（顧客または参加者の個人データを含まない）

顧客は、入力するメンバー、参加者、その他の人物データについて、適法な根拠、通知、必要な同意（未成年を含む）を確保する責任を負います。

## 4. 本ポリシーで使用する定義

- **オーナー** — 正確に 1 つの Organization ワークスペースを所有する有料 Check Station ユーザー。
- **ワークスペース / Organization** — 顧客のテナント境界およびサブスクリプション境界。
- **ワークスペーススタッフ** — そのワークスペース用に顧客が作成した admin または staff ログイン。オーナーアカウントでもメンバーでもない。
- **メンバー** — 顧客がワークスペースに保存する人物レコード。メンバーはワークスペースにログインしない。
- **参加者** — グループまたは Event キオスクを通じてチェックインする人物。メンバーおよびグループ限定参加者を含む。
- **Action Record** — 実行された出席または関連アクションの履歴レコード。
- **キオスク** — グループ（または Event 機能使用時は Event）が所有する参加者向けインターフェース。ワークスペース管理ダッシュボードではない。

## 5. 顧客が提供する情報

### 5.1 オーナーアカウント情報

オーナーが登録またはアカウントを管理する際、Check Station は以下を処理:

- ログインメールアドレス
- パスワード（使用する場合、復元可能な形式ではなくハッシュとして保存）
- サインイン方法でリンクした任意の Google または Apple サインイン ID
- メール認証状態および関連タイムスタンプ
- 任意のバックアップメールおよび認証状態
- 保留中のログインメール変更および関連タイムスタンプ
- 任意のオーナー二要素認証シークレット（保存時暗号化）

新規登録の有料オーナーは、Django 管理を使用するプラットフォームオペレーターを除き、ワークスペースアクセス前にメール認証が必要。

### 5.2 ワークスペーススタッフ情報

顧客はワークスペース admin および staff アカウントを作成可能。Check Station は以下を保存:

- ユーザー名（そのワークスペース内で一意）
- ハッシュ化パスワード
- 任意のメール（現在の製品では Admin ロールで必須）
- ロール（admin または staff）およびステータス
- 製品が使用するタイムスタンプおよびプラン関連フラグ

スタッフは **ワークスペース ID + ユーザー名 + パスワード** でサインイン。オーナーのメール認証フローには登録されません。スタッフ二要素認証は未実装。

### 5.3 メンバーおよび参加者情報

顧客が収集するフィールドを決定。現在の製品では、設定により以下を保存する場合があります:

- 名前（メンバーで必須）
- 任意のメール、生年月日、電話、住所、写真、メモ
- グループ参加メール（製品により数に上限）
- 設定された出席識別子および出席 PIN（出席 PIN は運用コードであり、アカウントパスワードではない）
- 再利用メンバーなしで使用するグループ限定参加者レコード
- 機能が有効な Structured Group のクラス／セクション出席 PIN

非推奨のメンバーチェックイン識別子および PIN ハッシュフィールドが保存レコードに残存する場合があります。

### 5.4 出席および Action Record

キオスクまたは認可されたアクターがアクションを実行すると、Check Station は Action Record を作成。レコードには以下が含まれる場合があります:

- Organization およびグループコンテキスト
- スナップショットとしての参加者種別および識別子
- 名前、メール、識別子スナップショット
- アクション種別（例: チェックイン、チェックアウト、休憩開始、休憩終了）
- ソース（例: キオスク、自動、オーナー）
- タイムスタンプおよび任意のキオスクメモ
- Structured ワークフロー用のクラス／グループスナップショット

Check Station は通常のアーカイブおよび無効化操作中も Action Record を保持。オーナーアカウントの完全削除は第 14 節に記載のとおり、そのワークスペースの運用 Action Record を削除。

### 5.5 キオスク設定およびセッションデータ

顧客はグループごとにキオスク動作（本人確認方法、許可アクション、ビジュアルデザイン、ロゴや背景）を設定。キオスク使用中、Check Station はオーナーまたはスタッフの既存 Check Station セッション Cookie を使用し、そのブラウザセッションをキオスクモードにロックして参加者にワークスペースダッシュボードを公開しない。

キオスクリロックはセッションデータ。未実装の専用デバイス資格情報の代替ではない。

### 5.6 写真およびその他メディア

顧客は以下をアップロード可能:

- メンバーおよび参加者の写真
- キオスクロゴ、背景、類似のデザインメディア

アップロード画像はワークスペースメディアとして保存。Check Station は表示用にコピーをリサイズまたは圧縮する場合あり。正確な本番画像仕様は未確定。アカウント完全削除は、現行実装でそのワークスペースの保存メディアファイルを削除。

### 5.7 顧客設定メール（グループ SMTP）

顧客はグループメール送信者（カスタム SMTP、Gmail アプリパスワード、Microsoft 365 SMTP、Yahoo アプリパスワード）を設定し、アクション後または参加メッセージを送信可能。Check Station は送信者ホスト／ポート／セキュリティ設定、ユーザー名、From 名／From アドレス、**暗号化** SMTP パスワードを保存。復号パスワードは顧客 API から返却されません。

配信監査レコードには受信者、メッセージ種別、イベント種別、ステータス、短いエラー概要が含まれる場合あり。これらのレコードは顧客ワークスペースに属する。

プラットフォーム Email Delivery（Resend）は顧客 SMTP とは別。「Email Delivery」の公開ステータス報告はプラットフォーム Resend を指し、顧客のグループ SMTP ではない。

### 5.8 請求情報

有料プランでは、Check Station はサブスクリプション状態、プラン、間隔、購入元（記録されている Stripe または Apple を含む）、トライアル／猶予／キャンセルフラグ、Checkout、Customer Portal、Webhook、権限の運用に必要な関連請求識別子を処理。

カード番号は決済プロバイダー（現在 Web チェックアウトは Stripe）が処理。Check Station は完全な支払いカード番号を保存するよう設計されていません。

Apple アプリ内課金の実行は未確定の製品項目。ワークスペース購入元が Apple の場合、Check Station は実装に従いそのワークスペースの Stripe 管理請求コントロールを非表示。

### 5.9 お問い合わせとサポート

Docs の公開 **サポート** ハブはセルフサービス。FAQ ページと同じ正規 FAQ コンテンツを検索し、コンパクトな公開 Status 概要を表示。アカウント不要。

公開 **お問い合わせ** ページ（および同じ Contact API を使用する将来のアプリ内 Contact クライアント）は以下を収集:

- 選択したカテゴリとサブカテゴリ
- メールアドレス
- 任意の名前
- 件名とメッセージ
- フォーム運用に必要な技術的スパム対策データ（レート制限用 IP アドレス、Cloudflare Turnstile チャレンジ結果、類似の不正利用防止メタデータを含む場合あり）

お問い合わせ送信は Contact リクエストレコードとして保存（送信メール失敗時もメッセージを失わない）。受理された送信は公開 Check Station お問い合わせアドレス（デプロイで別途設定されない限り `contact@checkstation.app`）にメール。これは公開ルーティングアドレス。Check Station は本ポリシーまたはアプリケーション設定で非公開転送メールボックスを公開しません。

Contact 経由のプライバシー、法務、データリクエストは**捕捉およびルーティング**されます。自動実行されません。

## 6. 自動収集される情報

Check Station は自動的に以下を処理:

- ブラウザ認証に必要なセッション Cookie および CSRF トークン（第 7 節参照）
- ソフトウェアが生成するセキュリティおよびアプリケーションログ
- 独立 Status サービス上の公開サービスステータスプローブ結果（コンポーネント名と公開状態のみ。顧客個人データではない）
- Web アプリケーション運用に通常の技術リクエストメタデータ（例: リクエストが発生したこと）
- 公開お問い合わせフォームについて、レート制限およびボット保護に使用する IP アドレスおよび関連スパム対策シグナル

Check Station は、文書化されたアーキテクチャの一部として、現時点で第三者プロダクト分析（例: マーケティング分析タグマネージャー）を**運用していません**。

Basic プランの広告は現在 **モック** 開発プロバイダーを使用。実際の広告ネットワークは接続されていません。実プロバイダー導入時、本ポリシーを更新して当該共有を説明する必要があります。

## 7. Cookie とセッション技術

Check Station ワークスペースは以下を含むファーストパーティ Cookie を使用:

- `checkstation_sessionid`（HttpOnly）— 顧客／ワークスペースセッション
- `checkstation_csrftoken`（アプリケーションから読み取り可能）— CSRF 保護
- `/admin` パス上の分離 Django 管理 Cookie（`checkstation_admin_sessionid` および `checkstation_admin_csrftoken`）

Cookie SameSite は現在のアプリケーション設定で Lax。本番 `Secure` Cookie フラグはデプロイ設定に依存し、ここでは universally 有効と断言しません。

公開 Status API および公開コンテンツ API はこれらの Cookie を要求しません。

## 8. 情報の利用目的

情報は以下のために使用:

- アカウント、ワークスペース、キオスク、出席機能の運用
- オーナーおよびワークスペーススタッフの認証とセッション保護
- プラットフォームトランザクションメールの送信（認証、パスワードリセット、メール変更通知、猶予中の支払い失敗警告などの請求通知）
- サブスクリプション、権限、プラン上限、アップグレード、ダウングレード、キャンセル、決済プロバイダーイベントの処理
- プランが広告を要求し**かつ**プラットフォーム広告キルスイッチがオンの場合、**Basic** ワークスペースでの広告配置表示（ライブ参加者キオスク操作中は除く）
- 不正、不正利用、不正アクセスの防止（お問い合わせフォームのレート制限およびボット保護を含む）
- お問い合わせメッセージおよびプライバシー／法務リクエストの受信と対応（捕捉とルーティングのみ。自動実行なし）
- 法令遵守および利用規約の執行
- Status サービスを含む信頼性向上と障害診断

顧客 SMTP 資格情報を Check Station マーケティングメール送信に使用しません。Action Record を履歴書き換えによる分析に使用しません。

## 9. サービスプロバイダー

設定により、Check Station は以下を使用:

- **Resend** — プラットフォームトランザクションメール。Contact 送信の公開 Check Station お問い合わせアドレスへの配信を含む
- **Cloudflare Turnstile** — 公開お問い合わせフォームのボット保護
- **Stripe** — Stripe 設定時の Web サブスクリプションチェックアウト、カスタマーポータル、関連決済処理
- アプリケーションとデータベース運用の**ホスティングおよびインフラ**（本番ホスティングプロバイダーとリージョンは本ポリシーで指定されていない）
- **Apple** — App Store 請求使用時のみ。ライブ統合は未完了

これらのプロバイダーは、Check Station デプロイに適用される条項と設定に従いデータを処理。

顧客設定 SMTP プロバイダー（Google、Microsoft、Yahoo、顧客自身のメールサーバー）は、顧客がグループメール経由で送信するものを受信。顧客が提供した資格情報を使用する顧客の処理。

## 10. 広告（Basic プラン）

**Basic** ワークスペースに広告が表示される場合あり。**Plus** と **Business** には表示されません。

現在の固定 Web 配置: ダッシュボードバナー、グループバナー、キオスク起動前、キオスク終了後、キオスクビルダー離脱時。ライブ参加者キオスク操作中、および現在指定のメンバー、履歴、スタッフ、アカウント画面には**表示されません**。

プラットフォームオペレーターはワークスペースプランを変えずに全広告をグローバル無効化可能。ローカル開発はモックプロバイダー。ライブ広告ネットワーク未接続のため、本ポリシーは広告ネットワークへの個人データ共有を主張しません。

## 11. 児童および未成年

Check Station は組織向けに販売。製品例に学校や保育を含むが、それらに限定されない。メンバーと参加者は一般に Check Station オーナーアカウントを作成しない。

Check Station は参加者向け年齢ゲートを提供しない。児童に関する情報を入力する顧客は、適用される児童プライバシー法および教育プライバシー法（必要な保護者同意の取得、必要な通知の提供を含む）を遵守する責任。Check Station は COPPA、GDPR-K 等の認定を主張しません。

利用規約違反で**オーナーアカウント**が児童により作成されたことが判明した場合、当該アカウントを削除する場合があります。

## 12. 国際処理

Check Station は複数国からアクセス可能。本番ホスティングリージョンは本ポリシーで指定されていません。情報は当時のインフラが所在する国で処理される場合があります。

日本の顧客は、収集を決定する個人データについて、個人情報保護法（APPI）および関連ガイドライン下の自身の義務を負う。本ポリシーは顧客の APPI 通知の代替ではありません。

## 13. 保持

Check Station はワークスペース存続中、アカウントおよびワークスペースデータを保持。

アーカイブと無効化は通常の可逆パスであり、Action Record を含む履歴を**保持**するよう設計。

アーカイブ後の Action Record の文書化数値保持スケジュール、削除後の法的ホールド／コンプライアンス保持システムは**未実装**。本ポリシーはログまたは出席履歴の特定年数を主張しません。

ローカル開発データベースはディスクボリュームに永続。本番バックアップポリシーではありません。

## 14. 削除

ライブ有料サブスクリプションが削除をブロックしていない場合、オーナーは Check Station アカウントを完全削除できます。組み込みの無料 Business トライアルのみでは削除はブロックされません。

完全削除はオーナーのみ（または管理のプラットフォームスーパーユーザー）。機密確認（パスワード再入力、または OAuth のみのオーナーはプロバイダー再認証）が必要で、製品上不可逆。

ライブ有料サブスクリプション（有料アクセスが継続する期間終了時キャンセル含む）は、有料アクセスが実際に終了するまで完全削除をブロックします。アカウント削除は Stripe 請求を自動キャンセルし**ません**。

現行実装では、完全削除は有料ユーザー、Organization、ワークスペーススタッフ、メンバー、グループ、キオスク設定、グループメール送信者および配信監査行、そのワークスペースの Action Record、そのワークスペースの保存メディアを削除。

サブスクリプションキャンセルは**アカウント削除ではない**。請求キャンセルは、オーナーがアカウントを削除するか別の保持ルールが適用されるまで、データを残したまま有料サービスを制限または終了させる場合あり。

真の削除後、オーナーメールは新規アカウントとして再登録可能。以前の認証トークンは削除されたユーザーを復元できません。

Stripe 等のプロバイダーオブジェクトは、そこでキャンセルまたは削除されるまでプロバイダー側に残存する場合あり。現在の削除実装はプロバイダー側の保証ワイプを文書化していません。

## 15. セキュリティ

Check Station は、アクセス制御、パスワードハッシュ、CSRF 保護、分離管理セッション、任意のオーナー TOTP、Django 管理の必須プラットフォーム admin TOTP、保存時暗号化（TOTP シークレットおよびグループ SMTP パスワードを含む）、参加者からワークスペース UI を遠ざけるキオスクセッションロックを使用。

出席 PIN およびクラス PIN は一方向ハッシュで保存される運用コード。管理者は設定・変更・リセットできますが、保存済み PIN 値は表示されません。ログインパスワードと同等ではありません。

送信または保存の方法に完全な安全はありません。Check Station は絶対的セキュリティを保証せず、本ポリシーで特定の認定（例: ISO 27001 または SOC 2）を主張しません。

## 16. プライバシー権利

居住地域により、個人データへのアクセス、訂正、削除、特定処理への異議の権利がある場合があります。

- **オーナー**はアカウント設定で多くのアカウントデータにアクセス・更新でき、上記の完全削除を要求可能。
- **ワークスペーススタッフおよびメンバー／参加者**は、データを入力した**顧客組織**に連絡。Check Station は一般に顧客とは独立して参加者の本人確認ができません。
- **日本:** APPI 権利が顧客のデータ主体として適用される場合、その顧客に対して行使。**オーナー**アカウントの運営者として Check Station が処理するデータに関するリクエストを除く。

根拠のない、反復的、または他者の権利やサービスセキュリティを侵害するリクエストは拒否する場合があります。

## 18. 変更

本ポリシーを更新する場合があります。Check Station コンテンツ API（および本ページ）で公開されるバージョン、最終更新タイムスタンプ、発効日が現在の公開メタデータ。重要な変更は記載の発効日に有効。法令で許される範囲で、発効日以降の継続利用は更新ポリシーの受諾を構成。

本ドキュメントは正規のため、Check Station コンテンツシステムで変更すると公開 Docs サイトおよび同じ API を取得する将来のアプリ内ビューアが更新。各フロントエンドへの別コピーは不要。
